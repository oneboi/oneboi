在Spring Boot中，依赖注入主要有三种方式：构造器注入、Setter注入和字段注入。此外，还有使用@Resource和@Inject等注解的方式进行注入，但Spring官方推荐使用构造器注入。下面分别给出这几种方式的例子。

1. 构造器注入（Constructor Injection）
   通过在类的构造方法上声明依赖，Spring容器在创建Bean时会自动传入所需的依赖。这是Spring官方推荐的方式，特别是对于必须的依赖。
2. Setter注入（Setter Injection）
   通过在类的Setter方法上使用@Autowired注解，Spring容器会在创建Bean后调用Setter方法注入依赖。
3. 字段注入（Field Injection）
   直接在字段上使用@Autowired注解，Spring容器会通过反射设置字段值。这种方式虽然简单，但不推荐，因为它不利于测试和不变性。
4. 使用@Resource注解
   @Resource是JavaEE的注解，也可以用于依赖注入，默认按名称匹配，可以指定name属性。
5. 使用@Inject注解
   @Inject是JSR-330的注解，需要添加javax.inject依赖，使用方式与@Autowired类似。
6. 方法注入（任意方法）
   除了Setter方法，还可以在任意方法上使用@Autowired注解，Spring容器会在创建Bean后调用该方法并注入参数。

## 关于final字段的注入

在构造器注入中，我们可以将依赖字段声明为final，因为构造器注入确保在对象创建时就会注入依赖，并且之后不会改变。例如：



```java
@Service
public class SomeService {
    private final IZytCheckitemsService iZytCheckitemsService;

    // 构造器注入，可以省略@Autowired
    public SomeService(IZytCheckitemsService iZytCheckitemsService) {
        this.iZytCheckitemsService = iZytCheckitemsService;
    }

    public void useService() {
        iZytCheckitemsService.doSomething();
    }
}
```



这里，`iZytCheckitemsService`被声明为final，因为它在构造器中初始化，并且之后不会改变。这是构造器注入的一个优点，它保证了依赖的不变性和线程安全性。

注意：只有构造器注入才能使用final字段，因为其他注入方式都是在对象创建之后才设置值。Setter注入和字段注入都不能用于final字段，因为final字段必须在构造器中初始化。

总结：Spring Boot中注入对象的方式有多种，但推荐使用构造器注入，尤其是对于必须的依赖。构造器注入允许我们将依赖字段声明为final，从而确保依赖不可变，并且便于测试。

## **关于 final 字段注入的实现**

对于你提到的 `private final IZytCheckitemsService iZytCheckitemsService;`，这通常是通过**构造器注入**实现的：

### **为什么 final 字段可以注入？**

1. **只能在构造器中初始化**：final 字段必须在构造器中初始化

2. **Spring 的工作方式**：

   java

   ```java
   // Spring 创建 YourService 的伪代码逻辑
   IZytCheckitemsService service = getBean(IZytCheckitemsService.class);
   YourService yourService = new YourService(service); // 通过构造器注入
   ```

   

### **final 注入的完整示例**

```java
@Service
public class YourService {
    // final 字段，必须通过构造器注入
    private final IZytCheckitemsService iZytCheckitemsService;
    private final AnotherService anotherService;
    
    // 构造器注入（可以省略 @Autowired）
    public YourService(IZytCheckitemsService iZytCheckitemsService, 
                       AnotherService anotherService) {
        this.iZytCheckitemsService = iZytCheckitemsService;
        this.anotherService = anotherService;
    }
    
    public void businessMethod() {
        // 使用注入的服务
        iZytCheckitemsService.doSomething();
    }
}
```



### **Spring 4.3+ 的新特性**

从 Spring 4.3 开始，如果类只有一个构造器，`@Autowired` 可以省略：

java

```java
@Service
public class YourService {
    private final IZytCheckitemsService iZytCheckitemsService;
    
    // 省略 @Autowired，Spring 会自动识别为构造器注入
    public YourService(IZytCheckitemsService iZytCheckitemsService) {
        this.iZytCheckitemsService = iZytCheckitemsService;
    }
}
```



### **优点**

1. **不可变性**：final 确保依赖不会在运行时改变
2. **线程安全**：final 字段是线程安全的
3. **强制完全初始化**：确保对象在创建时所有依赖都已注入
4. **便于测试**：可以轻松通过构造器传入 mock 对象
5. **代码清晰**：明确显示类的依赖关系

### **注意事项**

1. final 字段**不能**用于 setter 或字段注入
2. 如果有多个构造器，需要明确指定 `@Autowired`
3. 如果有可选依赖，可以配合 `@Nullable` 使用

### **推荐实践**

- ✅ 优先使用构造器注入 + final 字段
- ✅ 对于可选依赖，可以使用 setter 注入或 `@Nullable`
- ❌ 避免使用字段注入（不利于测试和封装）

这就是为什么 `private final IZytCheckitemsService iZytCheckitemsService;` 这种写法在 Spring Boot 项目中越来越常见的原因。

# Lombok @RequiredArgsConstructor 注解详解

## 什么是 @RequiredArgsConstructor

`@RequiredArgsConstructor` 是 Lombok 提供的一个注解，用于自动生成构造函数。它会为所有被 `final` 修饰的字段和被 `@NonNull` 注解标记的字段生成一个构造函数。

## 基本语法

```java
@RequiredArgsConstructor
public class ClassName {
    private final String field1;
    private final int field2;
    @NonNull
    private String field3;
    private String field4; // 不会包含在构造函数中
}
```

## 注解参数

```java
@RequiredArgsConstructor(
    access = AccessLevel.PUBLIC,     // 构造函数的访问级别
    staticName = "of"               // 静态工厂方法名（可选）
)
```

## 详细示例

### 1 基本用法

```java
import lombokRequiredArgsConstructor;
import lombok.NonNull;

@RequiredArgsConstructor
public class Person {
    private final String name;
    private final int age;
    @NonNull
    private String email;
    private String address; // 不会包含在构造函数中
    
    // Lombok 会生成如下构造函数：
    // public Person(String name, int age, String email) {
    //     this.name = name;
    //     thisage = age;
    //     if (email == null) {
    //         throw new NullPointerException("email is marked non-null but is null");
    //     }
    //     this.email = email;
    // }
}

// 使用示例
public class Main {
    public static void main(String[] args) {
        Person person = new Person("张三", 25, "zhangsan@example.com");
        System.out.println(person);
    }
}
```

### 2 静态工厂方法

```java
import lombokRequiredArgsConstructor;

@RequiredArgsConstructor(staticName = "of")
public class User {
    private final String username;
    private final String password;
    
    // Lombok 会生成：
    // private User(String username, String password) {
    //     this.username = username;
    //     this.password = password;
    // }
    // 
    // public static User of(String username, String password) {
    //     return new User(username, password);
    // }
}

// 使用示例
public class Main {
    public static void main(String[] args) {
        User user = User.of("admin", "password123");
        System.out.println(user);
    }

```

### 3 访问级别控制


## 注意事项

### 1 字段选择规则

- **包含的字段**：`final` 字段和 `@NonNull` 字段
- **不包含的字段**：非 `final` 且没有 `@NonNull` 注解的字段

### 2 构造函数顺序

字段在构造函数中的顺序与它们在类中声明的顺序相同。

### 3 与其他构造函数注解的关系

- `@NoArgsConstructor`：生成无参构造函数
- `@AllArgsConstructor`：生成包含所有字段的构造函数
- `@RequiredArgsConstructor`：生成包含必要字段的构造函数

### 4 空指针检查

对于 `@NonNull` 字段，Lombok 会自动添加空指针检查。

在Spring中，`@Autowired`和`@Resource`注解都用于依赖注入，但它们有一些区别。下面详细说明这两个注解的区别，并给出使用示例。

## 1. 来源不同

- `@Autowired`：是Spring框架提供的注解，属于`org.springframework.beans.factory.annotation`包。
- `@Resource`：是Java EE提供的注解，属于`javax.annotation`包。Spring框架支持该注解，但需要类路径下有Java EE API（在Spring 4+中，需要额外添加依赖，但Spring Boot默认可能不包含，需要手动引入）。

## 2. 默认注入方式不同

- `@Autowired`：默认按类型（byType）进行自动装配。如果有多个相同类型的bean，则按名称（byName）进行匹配（需要配合`@Qualifier`指定bean名称）。
- `@Resource`：默认按名称（byName）进行自动装配。如果未指定名称，则按类型（byType）进行装配。

## 3. 属性

- `@Autowired`：可以使用`required`属性来指定是否必须注入（默认为true）。还可以使用`@Qualifier`注解来指定具体注入哪个bean。
- `@Resource`：有`name`和`type`属性。可以通过`name`属性指定bean的名称，通过`type`属性指定bean的类型。

## 4. 适用场景

- `@Autowired`：通常用于Spring生态，更适合按类型注入的场景。
- `@Resource`：是Java标准注解，更适合希望按名称注入的场景，或者需要脱离Spring框架使用的情况。

## 5. 示例

### 使用`@Autowired`按类型注入

java

```
@Service
public class MyService {
    private final MyRepository myRepository;
    
    @Autowired
    public MyService(MyRepository myRepository) {
        this.myRepository = myRepository;
    }
}
```



### 使用`@Autowired`按名称注入（需要配合`@Qualifier`）

java

```
@Service
public class MyService {
    @Autowired
    @Qualifier("myRepositoryImpl")
    private MyRepository myRepository;
}
```



### 使用`@Resource`按名称注入

java

```
@Service
public class MyService {
    @Resource(name = "myRepositoryImpl")
    private MyRepository myRepository;
}
```



### 使用`@Resource`按类型注入

java

```
@Service
public class MyService {
    @Resource
    private MyRepository myRepository;
}
```



## 6. 注意事项

- 在Spring 4.3及以上版本，如果类中只有一个构造器，那么`@Autowired`可以省略。但是`@Resource`不能省略。

- 使用`@Resource`需要确保类路径下有`javax.annotation`包。在Spring Boot中，如果需要使用`@Resource`，可以添加以下依赖：

  xml

  ```
  <dependency>
      <groupId>javax.annotation</groupId>
      <artifactId>javax.annotation-api</artifactId>
      <version>1.3.2</version>
  </dependency>
  ```

  

  但注意，从Java 9开始，`javax.annotation`包被移除了，所以需要额外引入。

## 7. 推荐使用

- 在Spring项目中，通常推荐使用`@Autowired`，因为它是Spring原生注解，与Spring生态集成更好。
- 如果希望代码与Spring解耦，或者习惯按名称注入，可以使用`@Resource`。

## 8. 类似注解

- 除了这两个注解，还有`@Inject`注解（JSR-330），它与`@Autowired`类似，也是按类型注入，但功能没有`@Autowired`丰富（例如不支持`required`属性）。使用`@Inject`需要引入`javax.inject`包。

总结：`@Autowired`和`@Resource`都可以用来注入依赖，但它们的默认行为、来源和用法略有不同。在Spring项目中，可以根据个人或团队的偏好选择使用。

# **@Autowired 与 @Resource 注解的区别**

## **概述对比表**

| 特性                | @Autowired                                               | @Resource                      |
| :------------------ | :------------------------------------------------------- | :----------------------------- |
| **来源**            | Spring 框架原生注解                                      | JavaEE/J2EE 标准注解 (JSR-250) |
| **包名**            | `org.springframework.beans.factory.annotation.Autowired` | `javax.annotation.Resource`    |
| **默认注入方式**    | **按类型 (byType)**                                      | **按名称 (byName)**            |
| **必需性**          | 支持 `required=false`                                    | 不支持必需性配置               |
| **Qualifier 支持**  | 需要配合 `@Qualifier`                                    | 有 `name` 属性可直接指定       |
| **构造函数注入**    | 支持                                                     | 不支持                         |
| **Setter/字段注入** | 支持                                                     | 支持                           |
| **优先级**          | 按类型 → 按名称                                          | 按名称 → 按类型                |
| **空值处理**        | 可配置 `required=false` 允许空值                         | 找不到会抛出异常               |

### **2. 注入方式对比**

#### **@Autowired - 默认按类型注入**

java

```
@Service
public class OrderService {
    
    // 按类型注入，如果有多个同类型bean会报错
    @Autowired
    private PaymentService paymentService;
    
    // 配合 @Qualifier 按名称注入
    @Autowired
    @Qualifier("wechatPaymentService")
    private PaymentService wechatPayment;
    
    @Autowired
    @Qualifier("alipayPaymentService")
    private PaymentService alipayPayment;
}
```



#### **@Resource - 默认按名称注入**

java

```
@Service
public class OrderService {
    
    // 按名称注入，找名为 "paymentService" 的bean
    @Resource
    private PaymentService paymentService;
    
    // 明确指定bean名称
    @Resource(name = "wechatPaymentService")
    private PaymentService wechatPayment;
    
    // 指定类型（不推荐，容易出错）
    @Resource(type = PaymentService.class)
    private PaymentService alipayPayment;
}
```

### **4. 在构造器和Setter方法上的区别**

#### **@Autowired - 支持构造函数注入**

#### **@Resource - 不支持构造函数注入**

java

```
@Service
public class UserService {

    @Resource
```

### **5. 必需性配置**

#### **@Autowired - 可配置非必需依赖**

java

### **9. 常见问题与解决方案**

#### **问题1：多个同类型Bean注入冲突**

## **总结与建议**

### **使用指南**

| 场景                   | 推荐注解                     | 原因                                               |
| :--------------------- | :--------------------------- | :------------------------------------------------- |
| 构造函数注入           | `@Autowired`                 | `@Resource` 不支持构造器                           |
| Setter/字段注入        | 都可以                       | 根据团队规范选择                                   |
| 按名称明确注入         | `@Resource`                  | 语法更简洁                                         |
| 可选依赖注入           | `@Autowired(required=false)` | `@Resource` 不支持                                 |
| Spring Boot 项目       | 优先 `@Autowired`            | Spring 生态更原生                                  |
| 需要与非Spring框架集成 | `@Resource`                  | JavaEE 标准                                        |
| 有多个同类型Bean       | 根据情况选择                 | `@Autowired + @Qualifier` 或 `@Resource(name=...)` |

### **个人建议**

1. **新项目优先使用 `@Autowired`**：
   - 构造函数注入 + final 字段（不可变）
   - 更符合 Spring 的设计理念
   - 功能更全面（支持 required、构造器等）
2. **特殊情况使用 `@Resource`**：
   - 需要明确按名称注入时
   - 与 JavaEE/Jakarta EE 组件集成时
   - 遗留代码迁移
3. **保持一致性**：
   - 一个项目中最好统一使用一种方式
   - 团队内部制定编码规范

java

```
// 推荐的现代Spring Boot写法
@Service
public class MyService {
    // 必需依赖 - 构造函数注入
    private final UserRepository userRepository;
    private final EmailService emailService;
    
    // 可选依赖
    private final Optional<CacheService> cacheService;
    
    public MyService(UserRepository userRepository,
                     EmailService emailService,
                     Optional<CacheService> cacheService) {
        this.userRepository = userRepository;
        this.emailService = emailService;
        this.cacheService = cacheService;
    }
}
```



选择哪种注解主要取决于项目需求、团队习惯和与现有代码库的兼容性。
